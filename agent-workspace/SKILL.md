# Agent Workspace Skill (generic)

**Goal**: Ensure every artifact that any Hermes profile which enables this skill creates is automatically placed under a dedicated workspace inside `/home/asus/workspace-hermes/<profile>` where `<profile>` is the active Hermes profile name (e.g., `velda`, `steward`).

## How to use

1. **Enable the skill** in the desired Hermes profile (or any profile that should respect the workspace rule):
   ```
   hermes skill enable agent-workspace
   ```
2. **(Optional) Symlink** the skill into another profile’s active skill list so that profile also inherits the same workspace enforcement:
   ```
   ln -s /home/asus/.agents/skills/agent-workspace ~/.hermes/skills/agent-workspace
   ```
3. **Generate files** as usual – the skill will intercept write operations and prepend the appropriate workspace path automatically. For example, a command like:
   ```
   write_file path="notes.txt" content="My notes"
   ```
   will actually create the file at:
   ```
   /home/asus/workspace-hermes/${HERMES_PROFILE:-default}/notes.txt
   ```
   (`$HERMES_PROFILE` is the environment variable Hermes sets for the current profile; if not set, `default` is used.)

## Implementation notes

- The skill wraps the `write_file`, `patch`, and similar tools. When a **relative** path is supplied, it is resolved against the workspace directory derived from the active profile name.
- The workspace is **profile‑specific**; each profile gets its own sub‑folder (e.g., `velda`, `steward`).
- No changes are made to `USER.md`, `MEMORY.md`, or any configuration files – the skill operates purely at runtime.

## Safety \u0026 Scope

- This skill only affects file‑creation/write commands (`write_file`, `patch`, etc.) invoked by the agent. It does **not** modify existing files outside the designated workspace unless you explicitly provide an absolute path.
- Deleting or overwriting files outside `/home/asus/workspace-hermes/${HERMES_PROFILE:-default}` is blocked by the skill.
